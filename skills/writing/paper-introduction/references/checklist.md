# Introduction checklist

## Pass 1 — Motivation and gap

- [ ] The opening is a concrete setting (a failure mode, a cost, a scientific puzzle), not "In recent years, X has become important"
- [ ] The gap names a specific missing capability or unanswered question, not "prior work has limitations"
- [ ] A reader unfamiliar with the exact subfield understands why the problem matters within the first paragraph

## Pass 2 — Approach and contributions

- [ ] The approach sketch stays at idea level — no methods-level detail that belongs in Methods
- [ ] Contributions are numbered and each is checkable: a reader could point to the section/result/artifact that proves it
- [ ] Contribution bullets state outcomes ("we show X reduces Y by Z%"), not a table of contents ("we describe our approach")
- [ ] Claims match what the paper actually delivers — nothing promised here that Results/Discussion walks back

## Pass 3 — Structure and hygiene

- [ ] Position against prior work is brief; deep comparison is left to Related Work
- [ ] Terms/notation the reader needs immediately are defined; the rest is deferred
- [ ] A roadmap paragraph is present if the paper is long or has an unusual structure
- [ ] No citations are invented or half-remembered from prior training data

See [examples.md](examples.md) for before/after rewrites and common failure patterns.

## Comprehension (from real review)

- [ ] Plain-language statement of the whole idea by the second paragraph, using no coined vocabulary
- [ ] All named problems listed in one sentence before any is elaborated
- [ ] Called problems or challenges, not "properties" or "aspects"
- [ ] Distinctions the argument depends on are defined before use
- [ ] Contributions are findings and gains, not system components
- [ ] No contribution is an evaluation; each traces to a named problem
- [ ] Preview of what was found, not only of what was built
- [ ] No forward reference to a numbered equation or table
