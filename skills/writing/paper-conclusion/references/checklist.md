# Conclusion checklist

## Pass 1 — Restatement

- [ ] Problem and contribution are restated in 1–2 sentences, without re-deriving the setup
- [ ] Main evidence is summarized without introducing new numbers not shown earlier
- [ ] The takeaway is specific enough that a reader skimming only abstract + conclusion gets the paper's point

## Pass 2 — Consistency

- [ ] Claims here match the abstract and introduction — no quiet strengthening or softening
- [ ] Limitations acknowledged in Discussion are not contradicted by an upbeat conclusion
- [ ] No new citations or unaddressed claims appear for the first time here

## Pass 3 — Future work

- [ ] Future work (if included) lists 2–4 concrete, actionable directions, not "more data, more experiments"
- [ ] Each direction is prioritized or scoped (why this one matters next), not a flat list
- [ ] Directions already covered as limitations aren't repeated verbatim without added specificity

## Pass 4 — Length and tone

- [ ] Short relative to the venue norm (often 1/2–1 page) — no full-paper recap
- [ ] Ends with a direct takeaway, not "In this paper, we have proposed..." padding
- [ ] No vague inspirational closing line unsupported by the evidence

See [examples.md](examples.md) for before/after rewrites and common failure patterns.

## Comprehension (from real review)

- [ ] Answers the question the paper opened with, in its terms
- [ ] Does not re-walk the results; numbers appear only as support
- [ ] Each named problem addressed explicitly, by name
- [ ] Asymmetry in evidence strength between problems is stated, not smoothed
